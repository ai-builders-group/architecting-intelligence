# Companion tooling

Offline Python 3.12 tooling with standard-library runtime dependencies. All bundled
listings are invented toy fixtures. No manuscript or real listings are included.

Run tools without installing the package (replace the input paths for later use):

```sh
python -m companion_tooling check_slice EXCERPT.txt FULL_FILE.py
python -m companion_tooling generate --inventory tests/fixtures/repo/inventory.tsv
python -m companion_tooling normalize_headers --inventory tests/fixtures/repo/inventory.tsv
python -m companion_tooling check_pointers --pointers tests/fixtures/repo/pointers.txt --inventory tests/fixtures/repo/inventory.tsv
python -m companion_tooling l0 --inventory tests/fixtures/repo/inventory.tsv --excerpts tests/fixtures/repo/excerpts
```

`check_slice` accepts a fenced excerpt with `# excerpt of lst-N.M` as its first
code line, the legacy `{#lst-N.M}` fence attribute, or a standalone excerpt file
starting with the header. It strips leading and trailing whitespace and ignores
blank lines, headers, exact `...` or `# ...` lines and lines starting with
`# continues`. A first code-line path comment (`# path` or `# path:range`) is
ignored on either side; it can also precede the excerpt id header.
Trailing excerpt callouts `# (n)` with one or
two digits are stripped; full-file comment lines starting with `# --8<--`
(after optional indentation) are skipped. L0 uses the same alignment rules.
It prints
`aligned` (exit 0), `ambiguous` or `missing` (exit 1). Ambiguity means more than
one ordered mapping into the full file; L0 passes it and reports the id as info.
Ambiguity remains a failure for the slice-sync `check_slice` command.

The inventory's directory is the default repository root; `--repo` overrides it.
Its exact TSV header is `id`, `chapter`, `kind`, `full_path`, `class` (tabs).
Ids must be unique and canonical, chapters must match ids, paths must stay within
their chapter and repository, and earlier dependencies must exist and precede
the dependent id. Generation validates files before writing, sorts numerically,
uses portable relative links, and avoids rewriting unchanged output.

`normalize_headers` rewrites a full file's first-line path comment to
`# <repo-relative full_path>` from its inventory row, removing any line range.
It prints changed paths. Other lines and line endings are preserved; running
it again changes nothing. Files without a first-line path comment are untouched.

`check_pointers` prints the number resolved over the number supplied (`8/8` for
the toy inputs). Zero pointers, duplicate pointers, missing rows/files/pages,
and non-clickable or wrong links fail. Inline code, fenced or indented code,
comments, and images do not count as clickable links. The accepted destination
is the explicit relative Markdown destination generated by this tool.

L0 checks inventory and full files, rejects host-specific local paths and hostnames
in listing content and generated output, and checks each supplied excerpt
fixture at `EXCERPTS/lst-N.M.txt`. It requires every excerpt fixture when
`--excerpts` is given, verifies its id, rejects missing matches, and rejects
excerpt fixtures for cut rows. Omitting `--excerpts` skips excerpt checks.
Optional `--denylist PATH` also rejects paths containing a denylist term without
printing the terms. Without it, the built-in host-specific prefixes still apply.

Publication exports must omit every path listed in `SHIP_EXCLUDE`.
The private publication scanner and planted-leak tests live in `private_gate/`;
that directory is excluded from the Python distribution. The shipped `tests/`
contain only portable toy listings and no planted leaks.

Development checks: `python -m pytest`, `ruff check companion_tooling`, and
`mypy companion_tooling`. Chapter L1 passes every chapter Python file explicitly
to `python -m py_compile`. Runtime uses only Python
3.12's standard library; the three check tools are the only development tools.
CI uses `COMPANION_ROOT='.'` for the publication repository's inventory,
pointers and chapters. It runs L0 without excerpts, then check_pointers,
tooling-only ruff/mypy and chapter compilation. Actions are pinned by SHA.
The private publication gate is absent from CI. Local validation uses toy
inputs; the GitHub workflow was written without running it.

The private local evidence file `TOOLING_PROOF.md` is intentionally gitignored
and is not part of a public repository. Commands and negative-test exit codes
are recorded there. This repository has no remote and is not pushed.
